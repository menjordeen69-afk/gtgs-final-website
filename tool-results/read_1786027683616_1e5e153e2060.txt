    12→    12→6       # Netlify Database
    13→    13→7       
    14→    14→8       Netlify Database is a fully managed Postgres database built into the Netlify platform. It handles provisioning, migrations,
    15→    15→9       and database branching automatically. There is no setup beyond installing the `@netlify/database` package.
    16→    16→10      
    17→    17→11      Prefer Netlify Database over Netlify Blobs for any application data — records, collections, lists, user-generated content,
    18→    18→12      or anything you would store as rows. Use Blobs only for files, binary assets (images, video), or cached responses.
    19→    19→13      
    20→    20→14      ## CRITICAL: Use the `@beta` dist-tag for Drizzle
    21→    21→15      
    22→    22→16      The Netlify Database adapter for Drizzle ORM only exists on the `beta` release line of `drizzle-orm`. You MUST install
    23→    23→17      both `drizzle-orm` and `drizzle-kit` from the `@beta` dist-tag — the default `latest` versions do not include the
    24→    24→18      Netlify Database adapter and will fail.
    25→    25→19      
    26→    26→20      This affects:
    27→    27→21      - `npm install` commands: always install `drizzle-orm@beta` and `drizzle-kit@beta` (never `drizzle-orm` or
    28→    28→22        `drizzle-kit` without the tag).
    29→    29→23      - Import paths: use `drizzle-orm`, `drizzle-orm/pg-core`, and `drizzle-orm/netlify-db` as normal. No package
    30→    30→24        name rewriting is needed — the `@beta` tag only affects the installed version, not the imports.
    31→    31→25      
    32→    32→26      If you forget the `@beta` tag, `drizzle-kit generate` will error with a message about being outdated, or the
    33→    33→27      `drizzle-orm/netlify-db` import will fail to resolve.
    34→    34→28      
    35→    35→29      ## CRITICAL: Database schema changes always require migrations
    36→    36→30      
    37→    37→31      Any code change that assumes a different database schema (adding tables, adding columns, renaming fields, changing types,
    38→    38→32      adding indexes, etc.) will only work if a corresponding migration exists in `netlify/database/migrations/`. Without a
    39→    39→33      migration, the database schema will not change and the application will break at runtime.
    40→    40→34      
    41→    41→35      This applies regardless of whether you are using Drizzle ORM or the native `@netlify/database` driver:
    42→    42→36      - **With Drizzle ORM**: Update the schema definition, then run `npx drizzle-kit generate --name <descriptive_name>`
    43→    43→37      - **With native driver**: Write a new SQL migration file in `netlify/database/migrations/`
    44→    44→38      
    45→    45→39      Never consider a schema change complete without a corresponding migration file.
    46→    46→40      
    47→    47→41      ## Setup with Drizzle ORM (recommended)
    48→    48→42      
    49→    49→43      This is the recommended approach. It gives you type-safe schema definitions, a query builder, and automatic migration
    50→    50→44      generation.

    52→    52→46      ### Step 1: Install packages
    53→    53→47

    56→    56→50      npm install -D drizzle-kit@beta

    59→    59→53      ### Step 2: Create the schema file
    60→    60→54      
    61→    61→55      Create `db/schema.ts` at the project root. Define all your tables here using Drizzle's schema builder.
    62→    62→56      
    63→    63→57      ```typescript
    64→    64→58      // db/schema.ts
    65→    65→59      import { pgTable, serial, text, timestamp, integer } from "drizzle-orm/pg-core";
    66→    66→60      
    67→    67→61      export const users = pgTable("users", {
    68→    68→62        id: serial().primaryKey(),
    69→    69→63        name: text().notNull(),
    70→    70→64        email: text().notNull().unique(),
    71→    71→65        createdAt: timestamp("created_at").defaultNow(),
    72→    72→66      });
    73→    73→67      ```
    74→    74→68      
    75→    75→69      When adding tables with foreign keys:
    76→    76→70      
    77→    77→71      ```typescript
    78→    78→72      export const posts = pgTable("posts", {
    79→    79→73        id: serial().primaryKey(),
    80→    80→74        title: text().notNull(),
    81→    81→75        content: text().notNull().default(""),
    82→    82→76        authorId: integer("author_id").notNull().references(() => users.id),
    83→    83→77        createdAt: timestamp("created_at").defaultNow(),
    84→    84→78      });
    85→    85→79      ```
    86→    86→80      
    87→    87→81      IMPORTANT: Use snake_case strings for column names (e.g. `"created_at"`, `"author_id"`) to match Postgres conventions.
    88→    88→82      The Drizzle column variable names can be camelCase.

    90→    90→84      ### Step 3: Create the database client
    91→    91→85      
    92→    92→86      Create `db/index.ts`. This file initializes the Drizzle client with the native Netlify Database adapter.
    93→    93→87      
    94→    94→88      ```typescript
    95→    95→89      // db/index.ts
    96→    96→90      import { drizzle } from "drizzle-orm/netlify-db";
    97→    97→91      import * as schema from "./schema.js";

   101→   101→95

   104→   104→98      ### Step 4: Configure Drizzle Kit
   105→   105→99      
   106→   106→100     Create `drizzle.config.ts` at the project root. The `out` property MUST be set to `netlify/database/migrations` for
   107→   107→101     Netlify to automatically apply migrations.
   108→   108→102     
   109→   109→103     ```typescript
   110→   110→104     // drizzle.config.ts
   111→   111→105     import { defineConfig } from "drizzle-kit";
   112→   112→106     
   113→   113→107     export default defineConfig({
   114→   114→108       dialect: "postgresql",
   115→   115→109       schema: "./db/schema.ts",
   116→   116→110       out: "netlify/database/migrations",
   117→   117→111     });
   118→   118→112     ```
   119→   119→113     
   120→   120→114     ### Step 5: Generate migrations
   121→   121→115     
   122→   122→116     Every time you change the schema, run `drizzle-kit generate` with a `--name` describing the change
   123→   123→117     (max 50 characters, snake_case, starting with an imperative verb like add, create, drop, alter, rename, index):
   124→   124→118     
   125→   125→119     ```bash
   126→   126→120     npx drizzle-kit generate --name add_users_bio
   127→   127→121     ```
   128→   128→122     
   129→   129→123     Without `--name`, drizzle-kit assigns a random two-word name that says nothing about the migration.
   130→   130→124     
   131→   131→125     This creates SQL migration files in `netlify/database/migrations/`.
   132→   132→126
